  <action>
    Build the control module and expose it through the `task` backend.

    Control module — `halo_agent/subagent/control.py` exposes three functions:
    - `steer(child_session_id, text, *, store) -> admission_id`: enqueues a `session_admissions` row with `kind='steer'` for the child (reusing the Phase 3 `admissions.admit` path with `kind='steer'`); the child's next turn incorporates the steer text. Returns the admission id.
    - `kill(child_session_id, *, loop, core, store) -> None`: performs the three-pronged kill, in this order: (1) a loop `interrupt` — the child's current turn is interrupted (the Phase 3 turn close path with `close_reason='interrupted'`); (2) a core `abort` by the child's in-flight invocation `id` — the in-flight core work is aborted (the Phase 5 `HaloRpcClient.abort(id)`); (3) a per-session process-tree kill — every process the child spawned is reaped (see task 2 for the attribution mechanism; if D-G7-A2's fallback applies, use the provenance patch's session tag). The core is NEVER killed (it is shared); the kill is per-session. After the three prongs, the child's `turn_background_work` row transitions to `state='failed'` (via `finish_subagent_work`).
    - `restore(child_session_id, *, loop, store) -> None`: calls the Phase 3 `resume(child_session_id)` to reload the child's active transcript; the child can continue from where it was killed. The `turn_background_work` row is left in its terminal state (the restore does not re-open it).

    Task backend — extend `halo_agent/tools/backends/task.py` to expose the control operations: the handler accepts an optional `action` field (`'spawn'` (default, plan 01), `'steer'`, `'kill'`, `'restore'`) and an optional `child_session_id` (required for `steer`/`kill`/`restore`). For `steer`/`kill`/`restore`, the handler calls the corresponding `control` function. The parent can only control a child it spawned (the `child_session_id` must have `parent_session_id` = the parent's id; a mismatch is a typed error).

    Test — `test_steer_kill_restore.py` (SUB-03): a parent spawns a child (reusing plan 01's path); (1) steer: the user steers the child with a text; assert a `session_admissions` row with `kind='steer'` is enqueued for the child, and the child's next turn incorporates the steer text; (2) kill: the user kills the child; assert the loop `interrupt` happened (the child's turn closed with `close_reason='interrupted'`), the core `abort` happened (the in-flight core work was aborted), the process-tree kill happened (the child's processes were reaped — see task 2), and the `turn_background_work` row transitioned to `state='failed'`; assert the core is still alive after the kill (the shared core was not killed); (3) restore: the user restores the child; assert the child's active transcript is reloaded (the Phase 3 `resume` returns the child's transcript) and the child can continue (a new turn runs to completion).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user -> child session | The user's steer/kill/restore operations cross into the child session; a `child_session_id` the user supplies is untrusted |
| child session -> process tree | The child's `bash` tool spawns processes; these must be attributable to the child for orphan cleanup |
| child session -> shared core | The child's tool calls cross into the core (shared); a child's kill must not kill the core |

## STRIDE Threat Register

Threat IDs continue the phase register from T-07-04.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-04 | Denial of Service | a child kill that kills the shared core (taking down all sessions) | high | mitigate | The kill performs a per-session process-tree kill, never a core kill; the core `abort` is by the child's invocation `id`, not a core shutdown; `test_steer_kill_restore.py` asserts the core is still alive after the kill. |
| T-07-05 | Resource Exhaustion | orphaned processes or bound ports after a child kill | high | mitigate | The per-session process-tree kill reaps every process the child spawned; `test_orphan_cleanup.py` asserts no orphaned process or bound port remains. |
| T-07-06 | Tampering | a `child_session_id` the user supplies that is not the user's child (controlling another session) | medium | mitigate | The `task` backend rejects a `child_session_id` whose `parent_session_id` is not the caller's id with a typed error; the parent can only control a child it spawned. |
| T-07-07 | Tampering | a child session escaping its kill (a child that ignores the interrupt) | medium | mitigate | The three-pronged kill (loop interrupt + core abort + process-tree kill) ensures the child cannot escape: the loop interrupt closes the turn, the core abort stops the in-flight work, and the process-tree kill reaps the child's processes. |
</threat_model>
