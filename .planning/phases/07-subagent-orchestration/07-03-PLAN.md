  <action>
    Build the pool module and wire it into the `task` backend.

    Pool module — `halo_agent/subagent/pool.py` exposes two things:
    - `SpawnSemaphore(limit=3)`: a bounded worker pool / spawn semaphore (OMP `#spawnSemaphore` + `parallel.ts` `Semaphore` analog). `acquire()` blocks (or returns a queued state) until a slot frees; `release()` frees a slot. The default limit is 3 (D-G7-cap). A 4th concurrent `task` call is queued (not rejected) until a slot frees.
    - `depth_of(session_id, *, store) -> int`: reads the session's `parent_session_id` chain (following `sessions.parent_session_id` up to the root) and returns the recursion depth (the root is depth 0, its children are depth 1, their children are depth 2). The depth cap is 2 (D-G7-cap): a `task` call at depth 2 is a typed error; a child at depth 1 can spawn grandchildren at depth 2 (D-G7-nesting).

    Task backend — extend `halo_agent/tools/backends/task.py` to consume the pool: before spawning a child, the handler acquires a `SpawnSemaphore` slot (a 4th concurrent call is queued — the child's `turn_background_work` row is `pending` until a slot frees); the handler computes `depth_of(parent_session_id)` and rejects a `task` call at depth 2 with a typed error (the depth cap). The `SpawnSemaphore` slot is released when the child's `turn_background_work` row reaches a terminal state (`done`/`failed`).

    Test — `test_concurrency_cap.py` (SUB-04): (1) cap: a parent spawns 3 concurrent children (all run); a 4th concurrent `task` call is queued (the 4th child's `turn_background_work` row is `pending` until a slot frees); assert the cap is 3 (not 10, not unbounded); (2) depth: a `task` call at depth 2 is a typed error; a child at depth 1 can spawn a grandchild at depth 2 (the grandchild's `sessions` row has `parent_session_id` = the child's id, and the grandchild is at depth 2); assert the depth cap is 2.
  </action>
