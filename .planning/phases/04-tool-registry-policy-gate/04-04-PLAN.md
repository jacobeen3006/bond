<objective>
Complete GATE-03: the gate's third verdict action — rewriting arguments — becomes a real, provably narrowing operation, and every verdict leaves one complete, replayable decision row that the persisted tool row references.

**User story (MVP enrichment):** **As a** HALO user reviewing a session, **I want to** see exactly what the model asked for, what the gate actually allowed to run, and why, **so that** an argument the gate changed is visible as a change instead of looking like the model's own words.

Purpose: plans 01-03 proved allow and deny. Rewrite is the verdict most likely to hide something: it changes what runs while the transcript keeps the model's bytes, so it needs both hashes, a narrowing-only guard, and a byte-stable record. Decision-record completeness is also what Phase 12's bypass matrix and every later audit query read, so it is closed here rather than left implicit.
Output: the shipped rewrite rule (path normalization), the narrowing guards, the writer's same-transaction verdict pair, and `tests/policy/test_decision_records.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gate rewrite -> backend args | The one place policy changes what executes; an over-broad rewrite is privilege granted by the gate itself |
| model bytes -> persisted transcript | The audit narrative; rewriting it destroys the distinction between request and decision |
| verdict -> `policy_decisions` row | The audit record; a missing or partial row makes every later query a guess |
| decision row -> logs | Reasons, rule payloads and redaction lists must never carry a credential value |
