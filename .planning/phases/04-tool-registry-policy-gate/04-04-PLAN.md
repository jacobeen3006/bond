<objective>
Make deny-by-default a property of the evaluator rather than of one lucky code path: every failure mode the phase can name — unknown tool, unknown capability, wrong turn context, workspace escape, budget overrun, internal exception, no matching rule — ends in a deny that reaches a terminal invocation row with nothing executed.

**User story (MVP enrichment):** **As a** HALO user, **I want to** a tool call I never approved to be stopped by default rather than by exception, **so that** forgetting to allow something is safe and only an explicit decision lets a capability run.

Purpose: plan 01's gate carried four floor rules in one file. This plan makes the rule family real and provable — a named rule per deny, capability-class matching that cannot be laundered by a name, the Windows-correct path rule, and the purity plus budget properties the whole design rests on. Phase 5 registers shell- and file-capable tools on top of exactly these rules, so anything unproven here becomes a production hole there.
Output: `halo_agent/policy/rules/`, the wired evaluator, and four green test files covering GATE-02 and GATE-06 end to end.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request + snapshot -> gate | The single decision point; whatever it reads becomes part of the audit story |
| declared capabilities -> backend handler | A declaration that does not match what the handler does is a policy hole |
| entry `allowed_agents` -> turn context | Sub-agent and background contexts must not inherit main-context permission implicitly |
| arg paths -> workspace roots | A path-shaped argument escapes the user's workspace |
