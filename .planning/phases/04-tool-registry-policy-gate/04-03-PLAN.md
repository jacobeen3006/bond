<objective>
Make the registry the sole, auditable name authority and its catalog the model's only view of what exists: one name resolves to one backend or startup stops, and every name the model can see names the backend that will answer.

**User story (MVP enrichment):** **As a** HALO user, **I want to** the tool list my agent sees to be exactly the set of tools the gate will actually govern, **so that** the model can never be offered a capability that resolves somewhere unexpected.

Purpose: plan 01 proved one path works. This plan closes the two GATE-01/GATE-05 holes that a thin first slice leaves open — precedence enforcement (duplicates, code-registered claims, unregistered backends) and export honesty (winners only, backend disambiguation, stable order) — which are the properties Phase 5 depends on when it registers a dozen real tools at once.
Output: a hardened loader/registry pair plus two green test files, one of them the phase's first byte-pinned snapshot.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manifest + code registrations -> registry | Competing claims for one name; the resolution rule decides which backend a model-visible name reaches |
| registry catalog -> provider request | The only place model-visible capability is defined; anything exported is callable by the model |
| manifest entry -> backend registration | A row naming a backend nobody registered would otherwise resolve to a silent no-op |
