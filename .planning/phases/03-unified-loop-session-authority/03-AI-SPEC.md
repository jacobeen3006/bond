## 1. System Classification

**System Type:** Hybrid (Code Automation + Conversational + Autonomous, single loop)

**Description:**
HALO's single agent loop owns every model turn for the whole product: Desktop chat and CLI attach to the same daemon, and later surfaces (subagents, Kanban, GSD) are turns of this same loop. One SQLite store (WAL, FTS5) is the only transcript — sessions, transcripts, and turns persist there so any surface resumes the same conversation. "Good" means: exactly one loop per process, one history store, token accounting that matches the request actually sent, and a turn that closes only on an authoritative terminal signal. Built on the vendored MIT Hermes agent runtime (rebranded halo-agent, Python 3.14), model-agnostic over registered and OpenAI-compatible providers.

**Critical Failure Modes:**
1. Two histories: the transcript shown diverges from the request actually sent (mirrored-vs-sent identity breaks — LOOP-05).
2. Turn lifecycle lies: a turn is marked complete without an authoritative terminal signal, an outstanding background work item fails to keep it open, or a finished turn reopens (LOOP-06).
3. Compaction forks the lineage or token accounting drifts from bytes sent, so cost/context budgets are fiction (LOOP-04).
4. Resume/branch/export loses or corrupts session history — the single-store promise breaks at the boundary where users actually depend on it (LOOP-02, LOOP-03).
5. Steering, queueing, or interrupting a live turn corrupts loop state or silently drops input, breaking LOOP-01's "one loop owns every turn" contract.

## 1b. Domain Context

> Researched by `gsd-domain-researcher`. Grounds the evaluation strategy in domain expert knowledge.

**Industry Vertical:** Developer tooling — agentic coding-assistant runtimes. Phase 3's slice is the conversation-authority layer (the loop, the SQLite transcript, loop-owned compaction), not model quality.

**User Population:** Developers running HALO as their primary coding interface across multi-day sessions carrying real project state; every later surface (Desktop, CLI, subagents, Kanban) is a *client* of this one transcript, so its consumers are both humans and every future product surface built on it.

**Stakes Level:** High — no regulated-industry harm, full data-integrity stakes: the transcript is the product's only durable artifact, and a diverged or lost history silently destroys the user's work record and makes every derived claim (cost, context %, "what did the model see") unverifiable.

**Output Consequence:** The transcript is replayed into every future model request; resume, branch, export, and search are built on it; the context-% and cost figures shown to users derive from its accounting. If history diverges from what was actually sent, the agent acts on a false record of what it already did, users make decisions on false budget numbers, and bug reports ("the model ignored my correction") become unreproducible from the visible record.

### What Domain Experts Evaluate Against

The domain experts here are senior agent-runtime engineers and devtools maintainers. They do not judge model quality — they judge whether the loop tells the truth about itself.

**Dimension: Transcript fidelity (mirror-or-drop)**
- **Good (domain expert accepts):** every byte that entered the model request has exactly one transcript event plus a content hash — injected recall, policy reminders, compaction summaries, and ephemeral warnings all appear with provenance (`display_kind`), and the dev-build diff of `(seq, role, content_sha256)` between mirror and sent request passes every turn
- **Bad (domain expert flags):** a compaction summary or injected context sits in the request but not in the shown transcript — both sides are individually "correct" and the user's "the model ignored my correction" report cannot be reproduced from history; this is the product's documented hardest bug class
- **Stakes:** Critical
- **Source:** documented `context_message_added` pathology (PROJECT.md known pathologies; PITFALLS P-04); LOOP-05

**Dimension: Turn-lifecycle honesty**
- **Good (domain expert accepts):** a turn closes on exactly one predicate — the loop's terminal assistant signal AND zero outstanding background work bound to the turn; a yielded end with `awaitingAsyncWork` keeps the turn open; a closed turn never reopens; UI quiescence (`session_settled`) and turn completion are separate predicates, never derived from one another
- **Bad (domain expert flags):** completion keyed on frame type (`type == "agent_end"`) or on the UI going quiet; a backgrounded shell/task result appends to a "finished" answer or is silently dropped; the next user input fails with "Cannot continue from message role: assistant"
- **Stakes:** Critical
- **Source:** OMP RPC frame semantics (`isTerminal` / `yielded` / `awaitingAsyncWork`; PITFALLS P-04); earendil-works/pi issue #5886 (session settlement/continuation bug meta-issue)

**Dimension: Compaction lineage & accounting**
- **Good (domain expert accepts):** compaction is a generation rotation, not a fork — one active lineage (`active=1`), `message_uid` survives the rewrite, tool-call/result pairs are never split, the protected tail is byte-intact, and a failed pre-compress evidence checkpoint BLOCKS the rewrite instead of losing rows; context-% and cost derive only from provider-accepted `usage`, never from local estimates
- **Bad (domain expert flags):** context-% computed from a local estimator drifts from bytes sent — worst right after a compaction or injection, making budget numbers fiction; archived generations deleted as "duplicates"; or compaction silently eats recent turns so the agent forgets what it was just told
- **Stakes:** High
- **Source:** LOOP-04; Hermes context-engine accounting rules [doc]; arXiv 2606.22528 (compaction silently erases in-context constraints — "Governance Decay"); claude-agent-sdk-python #772 (compaction behavioral drift needs an audit trail)

**Dimension: Session durability (resume / branch / export after crash)**
- **Good (domain expert accepts):** kill the daemon mid-turn; on restart the admission FIFO resolves deterministically — a `started`-under-dead-owner admission becomes `unknown` and is NEVER replayed (side effects don't run twice), later inputs wait until resolved; resume rebuilds the active generation with uids intact; branch/export preserve parent uids and re-issue only physical row ids; recovery regenerates FTS indexes instead of trusting them
- **Bad (domain expert flags):** a dead-owner turn is silently replayed and an already-run shell command fires a second time; resume shows a session whose search index disagrees with its base table; export/import mints fresh uids, breaking the mirror invariant; a restart loses the last few pre-crash exchanges
- **Stakes:** Critical
- **Source:** Hermes durable-admission FIFO + recovery rules [doc session-storage]; LOOP-02/03; upstream's own reports: hermes-agent #13121 (restart resume loses immediate pre-restart context; transcript mismatch between stores), hermes-agent #5225 (interrupted turns neither recorded nor resumed), openai/codex #32973 (unclean-restart lifecycle-state divergence)

**Dimension: Steer & interrupt semantics**
- **Good (domain expert accepts):** an interrupt leaves a continuable history — every issued tool call gets a result row (real or synthetic) in original call order, no dangling `assistant(tool_calls)`, no partial assistant reply from an interrupted stream; steer folds into legal User→Assistant alternation; every admitted input has a durable queue record, so nothing vanishes without a trace
- **Bad (domain expert flags):** interrupt kills dispatch after the tool's side effect landed but before its result row persisted — the transcript says it didn't run, the workspace says it did; a steer appends a raw user row producing two consecutive user messages and the next request 4xx's; a queued follow-up disappears across a crash with no admission record
- **Stakes:** High
- **Source:** upstream interrupted-stream fill + alternation rules [doc agent-loop]; ARCHITECTURE §6 (synthetic results in call order, transactional cancellation); pi #5886; LOOP-01

### Known Failure Modes in This Domain

In this domain "the AI went wrong" means the loop lying about itself, not the model hallucinating:

- **Double-writer transcript / the demoted loop returns.** A wrapped `prompt`-class command re-enables a second loop with its own compaction and its own history, or an exception-path input writer appends speculatively without owner arbitration — two writers, one conversation, three independent divergence mechanisms (P-04). The demotion must be structural (turn-starting commands unwrapped, agent frames = protocol violation), never documented-only.
- **Compaction token drift.** Context-% from a local estimator vs provider-accepted usage; the estimate must measure the post-strip payload (upstream excludes `PERSISTENCE_ONLY_MESSAGE_FIELDS` from its own estimator for exactly this reason). Warning sign: provider-reported counts diverging from HALO's accounting after a compaction or injection (P-04; LOOP-04).
- **Interrupt mid-tool-call orphans side effects.** The cancellation boundary lands between the side effect and its result row: the workspace is mutated, the transcript is silent — and the dangling tool-call pair makes the next request malformed (4xx) or the session wholly uncontinuable.
- **FTS5 desync vs the base table.** The search index is trigger-synced over the active rows; recovery that copies row tables without regenerating the index leaves search returning archived rows or missing live ones — the session looks healthy while search lies.
- **>1 MiB truncation masquerading as model failure.** A naive line reader truncates physical stdout frames; oversized payloads require protocol-v2 chunk reassembly. Treating a completion frame's `messages` array as the transcript drops the prefix on oversized runs — the loss is size-dependent, so it only bites on long turns (P-04).
- **WAL on network paths.** SQLite WAL requires same-host shared-memory locking; a `state.db` on a network share sees lock stalls or page corruption. Upstream's own history: the silent WAL→DELETE fallback was escalated to a hard error after NFS/SMB/FUSE mounts turned the concurrency loss into blocked writers under the Kanban dispatcher; sibling agent runtimes carry open issues for WAL corruption and hangs on network-mounted homes (openai/codex #30957; anthropics/claude-code #96069). HALO's Windows-first layout already pins data dirs to `%LOCALAPPDATA%` — keep it structural: refuse non-local paths for `state.db`.

### Regulatory / Compliance Context

No regulated vertical: local, single-user Windows developer tool. HIPAA/GDPR/FCA-style regimes do not attach to the loop itself, and v1 explicitly scopes out multi-user/telemetry surfaces where such duties would arise. The two real obligations are engineering-honesty ones:

- **Secrets in the transcript and logs.** The transcript persists tool results verbatim and is replayed to providers on every turn; a token that enters history is a token shipped to a third party and exported with the session. The mirror rule (LOOP-05) deliberately persists bytes-as-sent, so redaction must happen at admission, not at render time; PLAT-06's redaction audit covers the log path. This is the most-reported real-world failure of this product class (GitGuardian research on keys reproduced from agent contexts; agents reading `.env` files and echoing secrets into sessions).
- **License provenance.** The loop derives from the MIT-licensed Hermes runtime; the MIT notice obligation survives the rebrand and travels with the vendored tree (P-02). Phase 3 code must not break the Phase 1 provenance ledger (IMPT-01..06) that keeps upstream security fixes reachable.

## 2. Framework Decision

**Selected Framework:** Custom loop over the vendored Hermes agent runtime (halo-agent) — no third-party orchestration framework

**Version:** Vendored MIT Hermes-agent subtree at its pinned import SHA (Phase 1 ledger); Python 3.14; provider transport in-tree; upstream cutoff — the fork is owned forever by decision.

**Rationale:**
Phase 3's requirements are the loop's own control seams — steer/queue/interrupt/follow-up (LOOP-01), one SQLite FTS5 transcript as the only history (LOOP-02/03), loop-owned compaction with send-accurate token accounting (LOOP-04), mirrored-vs-sent identity (LOOP-05), authoritative terminal signal (LOOP-06). The vendored Hermes loop already ships streaming, the interactive turn modes, and the FTS5 session manager, and the whole product (gate hooks, plugins, skills, Kanban, the Phase 2 wire contract, child-session subagents) is designed around its lifecycle. The Core Value ("one non-bypassable tool path") makes third-party ownership of turn state structurally unacceptable, and the upstream-cutoff constraint means any adopted framework would be forked and owned anyway — so take the loop you already own.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LangGraph (alternative kept warm) | Only third-party passing every hard constraint (model-agnostic, persistent state, streaming/interrupt semantics), but adopting it demotes the vendored Hermes loop to a hook host, re-bets Phases 2/11 against graph turn-semantics, and splits the transcript across its checkpoint format and HALO's SQLite store |
| OpenAI Agents SDK | OpenAI-optimized and no built-in persistent state — LOOP-02/03 IS the product; vendor lock-in violates constraints |
| Claude Agent SDK | Claude-only hard lock-in despite tempting hooks/compaction |
| Google ADK | Practical Gemini lock-in; no Google Cloud dependency acceptable |
| CrewAI | Matrix: avoid for fine-grained state, checkpointing, complex branching — i.e. the entire LOOP-01..06 surface |
| AutoGen / AG2 | Ecosystem fragmentation × upstream cutoff is the worst possible bet |
| LlamaIndex | Agent orchestration is not its strength; retrieval is Hindsight's job (Phase 8) |
| Haystack | NLP pipelines, not an agent loop |

**Vendor Lock-In Accepted:** No — model-agnostic over registered/OpenAI-compatible providers; the runtime is self-owned (the fork itself is the accepted trade-off, decided at import).

### Entry Point Pattern
```python
# Single-loop turn lifecycle — the Phase 3 contract, sketched from the documented
# upstream loop body [doc agent-loop], durable admissions [doc state.db], the turn
# data flow [evidence ARCHITECTURE §6], and the terminal-signal rule [evidence P-04].
# [PLANNED scaffold] — signatures are illustrative; provider/stream internals verify at SHA.

async def run_turn(loop, session_id: str, user_text: str, mode: str) -> "TurnResult":
    # mode: "prompt" | "steer" (redirect a live turn) | "queue"/"follow_up" (accepted now,
    # started after the current turn) | interrupt via turn.cancel. OMP documents these
    # turn-control verbs over RPC [evidence rpc.md]; HALO exposes them as daemon commands
    # on the one loop (LOOP-01) [PLANNED plumbing].

    # t0 — durable admission FIRST (Hermes session_admissions FIFO: queued -> started ->
    # terminal; an input `started` under a dead owner becomes `unknown`, is NEVER replayed,
    # and later inputs wait until resolved) [doc session-storage].
    turn_id = await store.admit_input(session_id, mode, user_text)

    # t1 — user row persisted before any provider call (append-only, single writer;
    # the insert mints message_uid) [doc].
    await store.append_user_message(session_id, turn_id, user_text)
    try:
        while True:
            if ctx.should_compress():                      # [doc] preflight at >50% window
                await ctx.compact(session_id)              # rotate transcript_id; old rows
                                                           # active=0; tool pairs never split
            messages = ctx.build_api_messages(session_id)
            # mirror-or-drop invariant (LOOP-05): every byte entering `messages` has exactly
            # one transcript event + content hash; api_content stores bytes-as-sent [doc].

            try:
                async for delta in provider.stream(messages, cancel=turn.cancel):
                    surface.emit(delta)                    # streaming feeds UI only — never
                                                           # persistence, never accounting
                reply = turn.finalize_assistant()          # one assistant row per provider call
            except TurnInterrupted:
                turn.discard_partial()                     # [doc] interrupted calls leave NO
                return await store.close_turn(             # partial response in history
                    session_id, turn_id, reason="interrupted")

            ctx.update_from_response(reply.usage)          # token accounting = bytes actually
                                                           # sent (LOOP-04) [doc]
            if not reply.tool_calls:
                return await store.close_turn(             # LOOP-06: close only on the
                    session_id, turn_id, terminal=True)    # authoritative signal (see below)
            results = await adapter.dispatch_batch(reply.tool_calls, turn.cancel)
            # Phase 4 fills the gate; Phase 3 keeps the seam. One row per tool_call_id,
            # in original call order regardless of completion order [evidence ARCH §2.1].
    finally:
        release_permits()                                  # every lane permit released here

# close_turn(terminal=True) may fire ONLY when is_turn_complete() holds: the loop's own
# terminal assistant signal AND no background work still bound to the turn (the
# awaitingAsyncWork analogue — auto-backgrounded shell/async child work keeps a turn open)
# [evidence OMP rpc.md frame semantics, PITFALLS P-04]. Async retain that already landed is
# NOT turn-bound: it finishes and its operation row is marked `unawaited`. A finished turn
# NEVER reopens; UI quiescence is a separate predicate (session_settled-style) — never
# derived from, nor used to derive, the other [evidence P-04].
```

### Common Pitfalls
1. **Treating a completion frame's `messages` array as the complete transcript.** For oversized runs the upstream encoder strips leading messages already delivered via `message_*` frames (and past 64 MiB falls back to an empty array + `messageCount`) — a snapshot of it silently loses the prefix, and the loss is size-dependent, so it only bites on long turns (LOOP-05). Persist from `message_start/update/end` only; the completion frame's payload is a convenience field [evidence OMP rpc.md, PITFALLS P-04].
1. **Keying turn completion on frame type instead of the terminal predicate.** A frame whose `isTerminal` is false, or that is a `yielded` end with `awaitingAsyncWork`, is NOT the end — marking it complete lets later tool results append to a "finished" answer or be dropped (LOOP-06, LOOP-01). Community precedent: earendil-works/pi issue #5886 — a meta-issue of session settlement/continuation bugs where post-run logic continues from a transcript that is not actually continuable ("Cannot continue from message role: assistant") [community]. One function owns the predicate; UI quiescence is a separate predicate; never derive one from the other.
1. **Unmirrored context.** A recall injection, policy reminder, or compaction summary that enters the model request without a visible transcript event is the product's documented hardest bug class: both sides are individually correct and the "model ignores my correction" report cannot be reproduced from the transcript (LOOP-05). The fix is a type-level invariant, not discipline: one function builds the sent request and emits `(seq, role, content_sha256)` per message; a dev-build check diffs it against the mirror every turn [evidence P-04].
1. **Compaction token drift.** Context % computed from local estimates drifts from bytes actually sent — worst after compaction or injection, making cost/context budgets fiction (LOOP-04). Accounting comes only from `update_from_response(usage)` on the provider response; upstream strips `PERSISTENCE_ONLY_MESSAGE_FIELDS` (`message_uid`, `_tool_call_uids`, …) before sending AND excludes them from its token estimator, so any HALO-side estimate must measure the same post-strip payload. Memory-side usage stays `purpose='memory'` in `session_model_usage` and is never folded into the turn's context percentage [doc + evidence ARCH §3.4].
1. **Double-writer transcript / the demoted loop coming back.** Any wrapped `prompt`-class command re-enables a loop with its own compaction, model selection, and transcript; exception-path input writers need explicit ownership arbitration (upstream arbitrates with an owner marker in the `display_metadata` sidecar — an unrelated writer never authorizes a speculative append [doc]). Demotion is structural: turn-starting commands are not wrapped at all; agent frames on a tool-backend session are protocol violations; `state.db` has exactly one writer — other processes and surfaces admit input to the owner instead of opening it for transcript writes [evidence P-04; doc session-storage].
1. **Reading 1 MiB frames with a small line buffer.** The coding core caps physical stdout frames at 1 MiB; oversized objects arrive as protocol-v2 `rpc_chunk` frames (base64, reassembled under a 64 MiB limit). A naive line reader truncates large tool outputs, which then masquerade as model failures (LOOP-05's >1 MiB turns). Negotiate v2 in the `ready` handshake; validate `chunkId/index/count/byteLength`; never surface chunk members individually [evidence P-04, ARCH §4.1].
1. **Alternation corruption through interrupt/steer paths.** Providers reject malformed histories: after system, strictly User→Assistant; tool loops are `assistant(tool_calls) → tool… → assistant`; never two assistant or two user rows in a row; only `tool` rows may repeat [doc]. An interrupt that leaves a dangling `assistant(tool_calls)` or a steer that appends a raw user row makes the next request 4xx — or makes the session uncontinuable (the pi #5886 failure) [community]. Upstream handles both ends: interrupted streams never inject a partial, and there is a documented interrupted-stream *fill* for row-addressed repair [doc]; steer must fold into a continuable shape.
1. **Deleting compaction archives as duplicates.** In-place compaction archives old rows as `active=0` and inserts retained context as `active=1`; a protected message legitimately exists in BOTH generations with identical content and timestamp [doc]. Diagnose duplicates on `active=1` only, key identity on `message_uid` (never row id or timestamp — the physical id is re-issued by every copy), and treat uid-preserving branch/compaction children as lineage, not duplication [doc context-engine].

## 4. Implementation Guidance

**Model Configuration:**
Model-agnostic by constraint — the loop speaks to registered providers and OpenAI-compatible endpoints through the upstream API-mode layer: `chat_completions` (OpenAI-compatible), `codex_responses` (Responses API), `anthropic_messages` (native Anthropic via adapter), resolved in order: explicit `api_mode` arg → provider-specific detection → base-URL heuristic → default `chat_completions`; all three converge on OpenAI-style internal message dicts [doc]. The catalog is OMP's provider catalog + role router (60+ providers, 9 roles, fallback chains, path-scoped models, round-robin credential pools [evidence FEATURES #14]) exported to Python as a **generated, versioned artifact with a startup compatibility check** — a second handwritten list will drift (SUMMARY open question #7). Credentials live in one secret store (Hermes secret store wins; OS keyring; never config/env) [evidence FEATURES].

Per-operation overrides are first-class reality, not a v2 nicety [doc unless noted]: fallback on failure class (429 / 5xx / 401-403 with credential refresh attempted before failover; plus failover on a reasoning-only stall with reason `incomplete_response`); auxiliary tasks (vision, compression/summarisation, web extraction) run their own `auxiliary.*` fallback chains independent of the main model; the **Memory Model inherits the main agent model by default** [PROJECT decision — the stale hard-coded provider default must never ship]; `update_model()` recalculates `context_length`/`threshold_tokens` on any model switch mid-session [doc]. Guardrail: `IterationBudget` default 500 iterations (`agent.max_turns`), subagents independently capped at 50 (`delegation.max_iterations`) [doc]. Per-turn sampling parameters come from the session's `model_config` column and the catalog role — never a loop-level constant; any specific default temperature is **[INFERENCE]** and must come from the catalog export rather than be chosen here. `max_tokens` is explicit per request (see 4b.3).

**Core Pattern:**
Single-writer loop + append-only SQLite transcript. The loop is the only writer; surfaces admit input; provider streams are transient.

```python
class SessionStore:                       # [PLANNED name] single-writer facade over state.db
    # WAL mode: concurrent readers (surfaces resume/list/search) + EXACTLY ONE writer.
    # Owns one writer connection on one task; every append mints message_uid at first
    # insert; tool rows carry tool_call_uids (assistant) / tool_call_uid (result) [doc].
    ...

async def persist_fragment(store, session_id: str, turn_id: str, msg) -> "StoredRow":
    row = TurnEvent.from_model(msg)                    # Pydantic model — see 4b.1
    stored = await store.append(row)                   # append-only; no in-place rewrites
    mirror_log.emit(stored.seq, stored.role, sha256(stored.sent_bytes))
    return stored
# Dev-build: diff mirror_log against the actual outgoing request bytes every turn
# (mirror-or-drop, LOOP-05). The api_content sidecar stores bytes-as-sent whenever
# they differ from display content — injections, persist overrides, compaction
# summaries — which makes LOOP-05 structurally checkable instead of aspirational [doc].
```

Three loop rules ride on it: **(1)** batch-first tool admission — resolve ALL calls in a response before ANY dispatch, so a denied/failed call can never leave a "half the batch ran" transcript state [evidence ARCH §2.1]; **(2)** one tool row per `tool_call_id` in original call order regardless of completion order — the loop only issues the next provider request once every id has a row [evidence]; **(3)** durable admission FIFO per session (queued → started → terminal) is what makes queue/follow-up crash-safe [doc].

**Tool Use:**
Phase 3's obligation is the **seam**, not the registry: every tool call leaves the loop through exactly one adapter boundary (`dispatch_batch` above) and returns `ToolResultEnvelope v1 { ok, text, content[], artifacts[], backend, invocation_id, policy_decision_id, duration_ms, truncated, error_kind? }` [evidence ARCH §2.1]. The transcript's `policy_decision_id` join exists from Phase 3 onward even while the gate itself lands with GATE-01/02 in the next phase (per `.planning/REQUIREMENTS.md` mapping): a dispatched tool row with no decision path is a defect, not a placeholder state. Registry + `contracts/tool-ownership.yaml` loader + capability classes + the pure `PolicyGate` slot into that seam later [evidence ARCH §2.2-2.3]; do NOT inline-dispatch tools in loop code, and DELETE the upstream agent-level interception table (`todo`, `memory`, `session_search`, `delegate_task`) rather than routing around it (bypass B7 [evidence]). Cancellation: one cancel-token tree per turn fans out to all in-flight invocations; unfinished ones get synthetic results in call order so history remains continuable after an abort [evidence ARCH §6 abort path].

**State Management:**
One authority: `state.db` SQLite (WAL), written only by `halo-agent`; OMP session files, Hindsight documents, and Electron state are never read back as conversation history [evidence invariant 3; doc "the profile's gateway is the only writer of canonical sessions" is the upstream rule HALO inherits]. Schema per [doc], with OMP tree semantics ported in [evidence FEATURES #12]: `sessions` (incl. `parent_session_id`, cost columns), `messages` (incl. `active`, `compacted`, `api_content`, `display_kind`, `display_metadata`, `message_uid`, `absorbed_message_uids`, `tool_call_uids`/`tool_call_uid`), `session_model_usage`, `messages_fts` + trigram + cjk FTS5 indexes synced by INSERT/UPDATE/DELETE triggers (indexed over content + tool_name + tool_calls), `session_admissions`, `runtime_epoch` (owner-epoch fencing: a stale owner's writes are rejected), `compression_locks` (cross-process compaction exclusion), `schema_version`.

- **Resume:** project the current transcript generation's `active=1` rows through the conversation-projection equivalent with `message_uid` restored unconditionally [doc]; resuming or continuing clears a sweep-only archive (`auto_archived`), never a deliberate one [doc].
- **List/search:** `session_search` is FTS5 over the single store [evidence FEATURES #17] — no second index. `recall` (memory) and `session_search` (what was said) are different verbs on different stores; neither writes the other [evidence].
- **Branch:** new `session_id` with `parent_session_id` lineage; copied rows KEEP the parent's `message_uid`s — upstream branch/export/import preserve uids, so the mirror invariant survives branching [doc context-engine]. Subagent transcripts live in the same store under the parent link so `agent://`-style addressing resolves without a second database [evidence FEATURES #12].
- **Export/import:** serialize active rows + uid manifest; import re-issues physical row ids and NEVER mints new uids [doc].
- **Crash:** a `started` admission whose owner died becomes `unknown`, is never replayed, and later inputs wait until resolved (`prompt.resolve_unknown` pattern) [doc] — no silent re-delivery of turn effects. Recovery copies row-bearing tables and REGENERATES FTS indexes; partial runtime ledgers are excluded, not adopted [doc].

**Context Window Strategy:**
Loop-owned compaction, single-sourced (LOOP-04):
- Exactly ONE `ContextEngine` implementation registered — the selection is single-select upstream and a second registration is rejected [doc]. OMP-side compaction is disabled at handshake (`set_auto_compaction {enabled:false}`) and `compact` is never sent — the coding core has no transcript to compact anyway; defense in depth [evidence ARCH §3.3-3.4].
- Triggers [doc]: preflight (before the API call) at >50% of the window; aggressive auto-compression between turns at >85%; manual guided `/compress <focus>` → `compress(..., focus_topic=…)`.
- Rewrite rules [doc]: memory/evidence checkpoint FIRST; middle turns summarized; last N messages preserved intact (`compression.protect_last_n`, default 20); tool-call/result pairs never split; `transcript_id` rotates with old rows archived `active=0`. The fail-closed `on_pre_compress` memory checkpoint is the Phase 3 seam (implementation Phase 6/7): a failed archive BLOCKS the rewrite rather than losing evidence [evidence ARCH §3.4].
- Accounting: `update_from_response(usage)` after every provider call; context-% shown to users derives ONLY from last accepted-usage, never an estimate; `update_model()` re-derives `threshold_tokens`/`context_length` on model switch [doc].
- Big turns: frames >1 MiB travel via protocol-v2 chunk reassembly [evidence ARCH §4.1]; the adapter caps inline tool-result bytes and spills larger payloads to the artifact store so one result cannot blow the window [evidence ARCH §2.1]. Provider context-overflow errors are handled as upstream's dedicated overflow/truncation turn phases — compact and retry — never ad-hoc history truncation [doc].

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice. All examples are written for THIS loop: custom Python 3.14 agent loop over the vendored Hermes runtime, hybrid Code-Automation + Conversational + Autonomous.

### Structured Outputs with Pydantic

There is no framework `.with_structured_output()` layer here — the custom loop parses model-produced JSON itself (tool-call arguments, engine-tool results, turn-event payloads for surfaces). Rule: **every model-produced structure passes a Pydantic v2 boundary before touching loop state**; a bare `json.loads` whose output reaches the transcript or the adapter is a defect. The models below encode the two identities the loop cannot fake: `message_uid` minting and the mirror hash.

```python
import json
import uuid
from datetime import datetime

        return [ToolCallIn.model_validate(c) for c in json.loads(raw_json)]
    except (ValidationError, json.JSONDecodeError) as exc:

        # grants exactly one bounded correction turn — same budget here [evidence
```

Retry policy in one line: validate → one correction attempt with the validator's own error text echoed as a tool result → surface. Validation failures are transcript events (the user sees why the tool "failed"), never silent re-rolls.

### Async-First Design

The HALO daemon is asyncio-first: surfaces attach over loopback HTTP/WS and the documented lifecycle awaits handlers (`await handler(args, ctx, cancel_token)`) [evidence ARCH §2.1, §1.1]. The **vendored core is thread-native**: `_interruptible_api_call` runs the HTTP request on a background thread watching an interrupt event, and concurrent tool batches use a `ThreadPoolExecutor` [doc]. Bridging those two models is where Phase 3 breaks:

- **The classic mistake — blocking the event loop:** calling the thread-native upstream entry synchronously from a coroutine, a sync `sqlite3` write, or a tokenizer pass inline on the loop thread. All blocking work goes through `asyncio.to_thread`/a dedicated single-writer task; `state.db` gets exactly one writer connection owned by one task (WAL makes readers free, the writer is serialized by construction).
- Second classic: `asyncio.run()` inside the running loop — the daemon IS the loop; surfaces, tools, and tests must never re-bootstrap it.
- **Stream vs await:** streaming deltas (`stream_delta_callback`-style [doc]) are for surface rendering ONLY — transient, never persisted, never the accounting source. Awaited results are the source of truth: the assistant row persists once at finalize, usage comes from the response, tool results are awaited and re-inserted in call order. Never conflate the UI's partial with the persisted row — the persisted row is what mirrors the next request's bytes (LOOP-05).
- Cancellation is transactional: one cancel-token tree per turn; every permit acquired during a turn is released in `finally`; in-flight invocations receive synthetic results in call order so the transcript stays continuable after aborts [evidence ARCH §6].

### Prompt Engineering Discipline

- **System vs user separation:** the system prompt is assembled by the prompt builder, kept STABLE, and cacheable [doc]. Recall injections, policy reminders, and plugin context are delimited, provenance-tagged **data** on the user side — never merged into the stable system prompt. Two structural reasons [evidence ARCH §6 notes]: prompt-cache prefix stability and injection resistance (tool output is likewise wrapped as data and never parsed for policy — bypass B17 [evidence]).
- **Ephemeral layers** (budget warnings, context-pressure notes) are applied per request upstream-style [doc] — but they are part of the bytes sent, so mirror-or-drop must record them (`api_content` / mirror log) or they violate LOOP-05 exactly the way the documented `context_message_added` pathology does [evidence P-04].
- **Few-shot:** inline and minimal in the stable prompt. Dynamic example retrieval is the memory side's job (Phase 7+), delivered through the same visible-data path, not as system prose.
- **`max_tokens` is explicit, never unbounded, in production:** it bounds the next window estimate and the per-turn cost budget (below); it interacts with `IterationBudget` (500/50 [doc]) — unbounded completions × 500 iterations is the runaway shape the budget exists to cap.

### Context Window Management

Agent compaction strategy — single-source lineage, send-accurate accounting (this system type's variant):
- **One engine, one implementation.** Single-select is enforced upstream: a second registration is rejected [doc]. All triggers are loop-owned (preflight 50% / auto 85% / manual focus-topic compression [doc]) — no subsystem compacts anything, especially not the coding core [evidence ARCH §3.4].
- **Lineage, not fork:** compaction is a generation rotation — `transcript_id` rotates, old rows flip `active=0`, `message_uid` survives the rewrite, and merged rows record witnesses in `absorbed_message_uids`; protected messages may exist in both generations by design [doc]. Identity queries use uid + `active=1`, never row id or timestamp.
- **Send-accurate accounting:** `should_compress()` compares `threshold_tokens` against the LAST `update_from_response(usage)` — what the provider actually accepted, not what an estimator thinks will be sent. Any local estimate must measure the post-strip payload (`PERSISTENCE_ONLY_MESSAGE_FIELDS` are excluded from the upstream estimator for exactly this reason) [doc].
- **Fail-closed evidence checkpoint before lossy rewrites** (`on_pre_compress` → memory provider): a failed archive blocks compaction rather than losing transcript evidence [evidence ARCH §3.4]; Phase 3 owns the seam, memory phases own the call.
- **Per-request context selection** (upstream `select_context()` hook) is request-only and never mutates persisted history — when Phase 7 uses it, it must return a STABLE selection when nothing changed or it silently forfeits provider cache reuse every turn [doc].

### Cost and Latency Budget

- **Accounting hooks ship now; pricing UI later.** Every provider call writes a `session_model_usage` row (per-model/per-task attribution [doc]); memory-side LLM usage is recorded `purpose='memory'` and never folded into turn context [evidence ARCH §3.4]. The `sessions` table already carries `estimated_cost_usd` / `actual_cost_usd` / `cost_status` / `pricing_version` [doc] — the loop fills them from catalog pricing metadata via the generated catalog export, never handwritten constants. Concrete $/turn figures are **[INFERENCE]** — they cannot be pinned before the catalog export (SUMMARY open question #7) and vendor pricing is versioned by `pricing_version`.
- **Structural cost guardrails:** `IterationBudget` (500 main / 50 child [doc]) caps runaway autonomy; ONE recall attempt per turn with visible degradation and no in-turn retry — retry-on-timeout is the documented metastable-failure amplifier (work that costs and returns nothing) [evidence P-05].
- **Cheaper models for sub-tasks:** summarisation/compression, vision, and web extraction run the independent `auxiliary.*` fallback chains [doc]; the Memory Model inherits the main model by default and is user-overridable [PROJECT decision]; per-role model routing comes from the exported catalog roles, not per-call whims [evidence FEATURES #14].
- **Caching:** exact-match only, via provider prompt caching (Anthropic cache markers upstream [doc]) — protected by prompt discipline (volatile content never precedes the cache prefix) and by stable `select_context` returns [doc]. No semantic response cache in Phase 3: recall is the budgeted L1 mechanism instead, capped one-per-turn [evidence P-05].
- **Latency budget:** track L0 time-to-first-token, turn p99, and sliding-window minimum queueing delay — never p50 alone; this product's own pathology hid in the median (p50 wait 11.59 s against 1.12 s of work) [evidence P-05]. CPU-only sidecar work (Phase 6 embedder/reranker) is a lane-time budget on local compute, not an API cost [evidence STACK/PROJECT].

## 5. Evaluation Strategy

### Dimensions

Phase 3 ships runtime plumbing over non-deterministic model calls, but every LOOP success criterion is an **invariant** — the loop either tells the truth about itself or it does not — and a scripted mock provider makes "what was actually sent" exactly knowable. The dimension suite is therefore dominated by deterministic code checks over mock-provider fixtures; the LLM judge is reserved for the single genuinely subjective residue (whether a generated compaction summary keeps what the middle turns said), and humans own golden-session labeling, close-edge adjudication, and dogfood sampling per the Section 1b roles table. Model quality is explicitly out of scope: these dimensions judge the loop, not the model.

| Dimension | Rubric (Pass/Fail, domain language) | Measurement | Priority |
|-----------|-------------------------------------|-------------|----------|
| **Transcript fidelity (mirror-or-drop)** | **PASS:** every byte that entered the model request has exactly one transcript event plus a content hash — injected recall, policy reminders, compaction summaries, and ephemeral warnings all appear with `display_kind` provenance — and the dev-build diff of `(seq, role, content_sha256)` between mirror and sent request passes every turn, including >1 MiB runs reassembled from protocol-v2 chunks. **FAIL:** a compaction summary or injected context sits in the request but not in the shown transcript; a completion frame's `messages` array is treated as the transcript and the prefix is lost on an oversized run. | Code — mirror-diff checker runs every turn in dev builds; fixture replay through the mock provider asserts row-by-row equality of mirror ledger vs sent bytes | **Critical** |

### Reference Dataset

**Size:** 12 golden fixture sessions to start — one per named failure mode below (≥ 10 per the framework; grow from real failures, never from hypothetical coverage). Built **during** implementation: every bug fixed in Phase 3 adds its fixture the same day.

**Composition (each maps a Section 1b failure mode → dimensions):**
1. Interrupt mid tool-call — cancellation lands after the side effect, before the result row (steer/interrupt, durability)
2. Interrupt during provider stream — no partial assistant injected, history stays continuable (steer/interrupt, lifecycle)
3. >1 MiB turn via protocol-v2 chunk frames — mirror and transcript byte-complete, no prefix loss (fidelity)
4. Compaction boundary — 50% preflight rotation: protected tail byte-intact, tool pairs unsplit, uid survival, `active=1` uniqueness (lineage)
5. Crash-mid-write — kill with a `started` admission under a dead owner: → `unknown`, never replayed, later inputs wait (durability)
6. Branch/export/import round-trip — parent uids preserved, only physical row ids re-issued (durability, fidelity)
7. Steer during stream — folds into legal User→Assistant alternation; never two user rows (steer/interrupt)
8. Queue drain — follow-ups admitted across a crash resolve FIFO in order; nothing vanishes unrecorded (durability, steer)
9. FTS desync probe — copy rows without the index; the audit checker must catch it and recovery must regenerate (durability)
10. Redaction-at-admission — canary tokens through user text, tool result, and log path; full-store sweep clean (compliance)
11. Terminal-signal variant matrix — `isTerminal=false`, yielded+`awaitingAsyncWork`, budget-exhausted, error: close ONLY on the authoritative predicate; closed turns never reopen (lifecycle)
12. Accounting drift probe — provider-accepted `usage` vs ledger across compaction and injection events, post-strip payload (lineage/accounting)

**Labeling:** per the 1b roles table — the **loop/session maintainer** records each golden session (scripted provider stream + store post-conditions the store MUST contain afterward); the **tech lead** adjudicates the turn-close edge cases (fixture 11's yielded+async-work and steer-race cases) and reviews the mirror-diff checker itself before its verdicts gate CI; compaction-summary fixtures carry human-labeled must-preserve constraint lists, and the LLM judge scores only after the 20-case calibration reaches ≥ 0.7 agreement. End-of-phase human verification (config `human_verify_mode: end-of-phase`): the **dogfooding developer** runs resume/branch/export round-trips on real multi-day sessions.

## 6. Guardrails

**Phase-3 scope note:** these are loop-level guardrails only. The PolicyGate guardrails (deny-by-default tool calls, approval modes — GATE-01..07) are the next phase's layer; their seam exists here (Phase 4 fills it) but their guardrails are NOT planned in this section.

### Online (Real-Time)

All five checks are O(1) — a predicate evaluation, a hash-set diff, or a regex over short strings — so none adds measurable turn latency:

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| **Terminal-signal close guard** | `close_turn(terminal=True)` fires while `is_turn_complete()` is false — missing terminal assistant signal or `outstanding_background_work > 0` | **Block** the close; the turn stays open and a typed event row records the refused close (LOOP-06) |
| **Mirror-or-drop send guard** | the per-request dev check finds a sent message with no transcript event + content hash, or a mirror row whose `(seq, role, content_sha256)` is absent from the built request | **Block** the provider send + flag the turn visibly — an un-mirrorable request never ships (LOOP-05) |
| **Secrets redaction at admission** | admission scanner matches a credential pattern in user text or tool-result text | **Block** raw persistence — redact before insert (mirror = bytes-as-sent, so admission is the only correct site); the log path gets the same treatment for PLAT-06 |
| **Alternation validity guard** | the projected request history violates User→Assistant / tool pairing (two assistant or two user rows, dangling `assistant(tool_calls)`) | **Block** the provider send + flag the corrupting turn — the pi #5886 "Cannot continue" class caught before it 4xx's |
| **Dead-owner admission guard** | recovery finds a `started` admission whose `runtime_epoch` owner is gone | **Block** replay — mark `unknown`, hold later inputs until resolved; side effects never run twice (LOOP-02) |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Turn-reopen attempts (count + turn reference) | every attempt is a loop event; dogfooding developer reviews weekly alongside the Section 7 sample queue | any occurrence is a lifecycle defect — triage against the terminal-signal fixture matrix (#11) and extend it |
| Accounting-drift samples | per-turn `provider usage − HALO ledger`; sample elevated-drift turns plus EVERY turn crossing a compaction or injection event | > 2 % drift or any compaction-boundary step → audit the post-strip estimator path before context-%/cost panels are allowed to show the number |
| Compaction ratio drift | `compression_count` + context-% step anomalies per rotation, plus calibrated LLM-judge scores on sampled summaries | judge-score regression or anomalous ratios → review middle-turn summaries against must-preserve constraints; tune `protect_last_n`/thresholds |
| FTS vs base-table mismatch audit | background checksum job per session at idle: index membership vs `active=1` rows and content | nonzero delta → regenerate the index (the recovery rule) and investigate the writer/trigger path |
| Unknown-admission age & dropped-steer reports | queue of unresolved `unknown` admissions + dogfood re-entry signals (user re-types identical text within 30 s) | any aging unknown → explicit resolve path in the surface; dropped-steer reports triaged against the queue-drain fixture (#8) |

## 7. Production Monitoring

**Tracing Tool:** **Transcript-as-trace** — consistent with the Section 5 Phoenix override: no server, no OTel collector, no Docker; the desktop app already ships its durable, content-addressed trace store.
- `state.db` IS the trace: session/message/turn rows are the spans (`turn_id` groups, per-session `seq` orders, `session_model_usage` carries per-call cost, the `TurnClose` record holds the close predicates). A replay view (`halo trace <session>` — [PLANNED] CLI verb) is a query over the same store the product shows, so monitoring can never diverge from the transcript.
- Structured loop events: JSONL under `%LOCALAPPDATA%\HALO\logs\` (`loop-YYYYMMDD.jsonl`): `turn_start`, `admission_state_change`, `request_built(bytes_hash, msg_count)`, `usage_accepted`, `compaction_rotated`, `mirror_diff(pass|fail+delta)`, `close_predicates(terminal, outstanding_background_work)`, `recovery_unknown_admission`, `redaction_applied`. Correlation keys: `session_id` / `turn_id` / `message_uid`; the PLAT-06 redaction path applies here identically to the transcript.

**Key Metrics to Track:**
1. Mirror-diff violations per turn — invariant: zero
2. Lifecycle anomalies — closes without the terminal predicate + reopen attempts: zero
3. Accounting drift — |provider-accepted usage − HALO ledger|, weighted on turns crossing compaction/injection events
4. Crash-recovery health — unresolved `unknown` admissions, silent-replay count (zero), pre-crash retention (resume must contain the last N persisted rows)
5. Search integrity — FTS-vs-base-table audit status per session

**Alert Thresholds:**
Single-user desktop: **no pager** — every threshold breach becomes a developer-visible degraded signal: a durable event row on the affected turn/session, a red badge in the session list, and an ERROR line in the JSONL log.
- Zero-tolerance invariants (mirror-diff fail, predicate-less close, reopen attempt, silent replay): ANY occurrence → in-transcript flag + session-list badge; CI (`just eval`) hard-fails the build.
- Accounting drift: any compaction/injection-boundary step, or > 2 % otherwise → the context-%/cost panel shows an "unverified" marker for the affected turn instead of a false number.
- FTS audit mismatch: session-list banner "search index rebuilding" + automatic regeneration job (visible, self-healing).
- `unknown` admission surviving one resume: the session opens in an explicit "input unresolved — review before continuing" state instead of silently proceeding.

**Smart Sampling Strategy:**
No cloud telemetry (v1 scope). The sampler runs locally over dogfooding usage and weights a weekly human-review queue (dogfooding developer + tech lead, 1b roles table) toward concerning signals:
- any turn flagged by an online guardrail (mirror, alternation, redaction, refused close)
- turns containing an interrupt during the tool-call phase, a compaction rotation, crash-recovery involvement, or a provider fallback/failover
- oversized runs: > 1 MiB physical frames; turns over 60 s wall time (never p50-only latency — this product's own pathology hid in the median [evidence P-05])
- user behavior signals: identical text re-entered within 30 s (dropped-steer suspicion), resumes following an abnormal exit
- a random 5 % baseline to catch signal-metric divergence — the early warning that the signal filters themselves have a blind spot

Every reviewed failure not already covered becomes fixture 13+ in the Section 5 dataset: the ledger grows from real failures, closing the flywheel.
