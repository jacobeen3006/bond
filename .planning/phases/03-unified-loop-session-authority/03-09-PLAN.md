<objective>
Make the one store usable: a user can resume, list, search, branch, export and import a session, and every one of those operations preserves the identities the rest of the product keys on.

**User story (MVP enrichment):** **As a** developer, **I want to** find an old session, branch it, and carry it to another machine without losing message identity, **so that** my history remains one searchable, portable conversation rather than a set of exports that disagree with the store.

Purpose: LOOP-03 is where users actually depend on the single-store promise. The risk is not storage; it is silent identity loss at every copy boundary.
Output: the session verbs, the minimal `halo-agent sessions` CLI surface, uid-preserving branch/export/import, FTS5 search with the upstream sanitizer, and round-trip tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user query -> FTS5 MATCH | Untrusted text reaches a query language |
| import file -> store | An attacker-supplied JSON document crosses into the write path |
| export file -> filesystem | The only document that leaves the home |
| branch -> parent lineage | Copying must preserve identity, not mint it |
