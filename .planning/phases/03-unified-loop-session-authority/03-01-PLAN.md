<objective>
Stand up the Python project that Phase 3's authority layer lives in, lock the open package-root decision, and prove the one-store promise with a real round trip: create the WAL transcript, write a session and a message, and read them back from a second process.

**User story (MVP enrichment):** **As a** HALO contributor, **I want to** open one SQLite transcript from the runtime and from a separate reader process, **so that** every later surface has exactly one history to read and no surface ever needs its own database.

The ROADMAP Phase 3 goal ("One agent loop owns every turn and one SQLite transcript is the only history") is outcome-shaped, not a user story; the sentence above is a faithful restatement of that goal and introduces no scope beyond it.

Purpose: every later plan in this phase verifies through `uv run --project packages/halo_agent pytest`; this plan creates that lane, the schema every store plan depends on, and the package-root contract that decides where imports resolve for the rest of the product.
Output: a synced uv project at `packages/halo_agent/`, the transcribed Phase 3 DDL, a writer-thread store with a read-only reader path, and two green test files.

**Why the split is safe (file-count trade-off, recorded):** the 18 declared files are one project skeleton, one DDL file, four runtime modules, two test files and the decision record; only `schema.sql` and `store.py` carry real logic. The schema, the writer thread and the cross-process read fail together — a split would commit a `schema.sql` that no reader ever opened and a writer whose WAL pragma was never proven, which is exactly the state the phase exists to make impossible. Every later plan's verify command resolves through `uv run --project packages/halo_agent pytest`, so the lane must be green in the same commit that creates it. The 18 declared files are spread across three tasks, not one: the two decision checkpoints own `03-DECISIONS.md`, the tracer owns the 13 files on the record path (project, DDL, migrations, writer, cross-process read), and a third task owns the environment probe plus the `just test`/`eval` recipes.
