<objective>
Make a live turn controllable without corrupting history: steer, queue, follow-up and interrupt each leave a durable, continuable transcript in a legal role alternation.

**User story (MVP enrichment):** **As a** developer watching a long turn, **I want to** redirect or stop it and have my input either applied or queued, **so that** the next request is well-formed and nothing I typed disappears.

Purpose: every documented agent-runtime failure in this class comes from an interrupt that leaves a dangling tool call or a steer that appends a second user row. This plan turns the ordering rules into code plus fixtures.
Output: input modes, steer folding, synthetic interrupt results, queue draining, and an alternation validator on the projection path.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live input -> in-flight turn | Steer/queue/interrupt arrive while the turn owns state |
| cancellation -> tool side effects | A cancel can land between a side effect and its result row |
| projection -> provider request | An invalid alternation becomes a provider 4xx or an uncontinuable session |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-3-01 | Tampering | `AgentLoop.steer`, `enqueue`, `interrupt` | high | mitigate | One loop owns the turn; interrupts use the loop's cancel tree; a second authority still raises `SecondLoopDetected`. |
| T-3-08 | Tampering | interrupted `dispatched` invocations | high | mitigate | `dispatched -> unknown` with `error_kind='side_effect_unknown'`; never claim the tool did not run; every call gets a result row. |
| T-3-05 | Repudiation | steer merge witnesses | high | mitigate | Merged rows keep the first `message_uid` and record `absorbed_message_uids`, so identity survives the fold. |

</threat_model>
