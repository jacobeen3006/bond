<objective>
Prove the phase's central claim: one loop owns the turn, it is the only thing that can build a request or close a turn, and a second authority — whether a hostile import or a wrapped command — is refused rather than documented away.

**User story (MVP enrichment):** **As a** developer, **I want to** run a turn through exactly one agent loop that persists its own history, **so that** every later surface observes the same conversation and no plugin can quietly start a second one.

Purpose: LOOP-01's "no alternate loop exists in the process" is a proof obligation, not a design note. Four gates (static import graph, runtime authority, store ownership from plan 02, and the adapter protocol check) make it testable.
Output: the vendor facade, `LoopAuthority`, `AgentLoop` with one real turn, the dispatch seam, the AST gate, and tests that attempt each violation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vendored runtime -> HALO loop | The facade is the only import path; the vendored instance must not own a session DB |
| plugin/test code -> loop construction | A second authority would be a second turn owner |
| tool backend -> loop | A wrapped turn-starting command would re-enable the demoted loop |
| provider stream -> transcript | Deltas must never become persisted rows |
