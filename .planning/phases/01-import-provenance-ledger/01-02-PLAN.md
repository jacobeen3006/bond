**As a** maintainer, **I want to** run the whole import on a hermetic ten-file repository and see it refuse hostile paths and filter-mangled bytes, **so that** the importer's safety and byte fidelity are provable offline before it touches three more real trees.

Purpose: the real trees are 2.7 GB and network-bound. Negative behavior cannot be proven against them (you cannot ask GitHub for a tree with a case collision). This plan builds the fixture that all later negative tests reuse, and wires the preflight gate that makes hostile input a refusal instead of a half-written tree.

Output: `tests/provenance/fixtures/make-fixture.ts`, the representability extension to `tools/provenance/paths.ts`, the gate call inside `stage.ts`, and three test suites.

Scope note (estimate 120k vs the 100k advisory budget, confidence low): no split is taken. The fixture builder, the gate it feeds, and the wiring that makes the gate unavoidable are one unit — separating the builder from its consumers would leave an unverified builder whose output every later negative test depends on. The plan stays one wave and one commit shape.
</objective>

  <action>
Extend the `tools/provenance/paths.ts` module created in plan 01-01. The 01-01 gate (`assertSafeArchiveEntries`, throwing on `absolute`/`traversal`/`unc`/`ads`/`backslash`/`empty-segment`) stays the extraction-time hard stop; add one representability entry point beside it, `validateTreePaths(paths: string[], options: { maxLength?: number }): Finding[]`, where `Finding = { kind, path, detail }` and `kind` is one of `absolute`, `traversal`, `ads`, `reserved-name`, `trailing-dot-space`, `case-collision`, `too-long`. Both entry points share one normalization function so the two can never disagree; `validateTreePaths` returns findings and never throws, `assertSafeArchiveEntries` throws on the escape classes.

Normalization: POSIX separators, a leading `./` stripped, rejected when absolute, containing a `..` segment, starting with `//`, containing a `\`, or containing `:` anywhere (a drive-letter form is absolute and already rejected).

Rules, from Microsoft's documented naming constraints: reserved device names are `CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, matched case-insensitively as a whole path segment, with or without an extension, and also with a trailing extension chain (`NUL.txt`, `NUL.tar.gz`). A component ending in `.` or a space is a finding. Case collisions are detected by lowercasing every path with `toLowerCase` and grouping duplicates; the finding carries both original paths. Length is measured on the full vendored path (`vendor/<tree>/` prefix plus the relative path) against a default of 240 characters — report the measured length in `detail`.

Write `tools/provenance/test/win-paths.test.ts` with the six negative groups and the clean-tree case from the behavior block, plus one positive case: a path containing a space but no trailing space, and a path with a Unicode name, both pass. Each test asserts the finding `kind` and that `finding.path` equals the input (so a future refactor cannot report the wrong path). Add a parity case: the same input list that throws `assertSafeArchiveEntries` also yields a finding from `validateTreePaths` with the same path and a matching kind.

Extend `stage.ts` with the preflight sequence and a filter detector, and expose both through `cli.ts` (`import`, `check-attributes`). `cli.ts import` gains a `--fixture happy|hostile` mode that builds the fixture into a temp cache and drives the identical code path with no network, so the negative behavior is reproducible offline. The preflight runs in this order and stops at the first non-empty stage: (1) `git ls-tree -r <sha>` on the cache; (2) `paths.ts` validation over the relative paths with the real vendor prefix; (3) gitlink gate — any entry with mode `160000` is exit 2 with `submodule entry: <path>`; (4) symlink gate — for each `120000` entry, read the link text from the blob and reject a text that is absolute, starts with `\\`, or normalizes outside the subtree (T-1-11); (5) size measurement printed as `SIZE <tree> files=<n> bytes=<n>` so the operator sees it before the commit. Only after the preflight does extraction run. Never follow a symlink while staging: read the link text from the object database with `git cat-file -p` and register it with `git update-index --add --cacheinfo 120000,<blob>,<path>`.

The detector is `checkAttributes(treeRoot, paths)` in `stage.ts`: for each path, compare `git ls-files -s`'s OID against `git hash-object --no-filters`'s OID and against the recorded upstream OID, and return `{ ok, mismatches: [{ path, indexOid, rawOid, upstreamOid }] }`. Also read `git check-attr text eol filter ident working-tree-encoding -- <path>` and flag any attribute that is `set` or has a non-`unspecified` value.

| upstream tree → local filesystem | Archive entries choose the paths that get written |
| ledger/CLI input → path handling | A path string from a manifest or a patch can name an escape |
| git index → committed bytes | An attribute can rewrite bytes between disk and object database |
