Output: the lookup tool, the two lookup suites, the synthetic rename fixture, the permanent CVE drill, and the runbook.

</objective>

Write `tools/provenance/where.ts` exporting `resolveUpstreamPath(path, tree)` and `lookup(query, trees)` plus a main guard so `bun run tools/provenance/where.ts <query> [--tree <name>]` works before `cli.ts` is wired. Resolution order exactly as specified: exact `exceptions` match (a `to: null` means deliberately absent), then the longest matching `prefix` rule (compare the length of the matched `from`), then an exact `file` rule, then identity. Never resolve by walking the filesystem: the answer must come from the ledger, and the filesystem check is a separate `exists` line so a ledger/tree mismatch is visible rather than masked.

Output format, one record per line and stable: `PATH <upstream> -> <local> (rule=<prefix|file|exception|identity> watch=<id|none>)`, then for symbol queries `SYMBOL <name> -> <local> (watch=<id>)`. Exit codes: 0 when at least one result was found; 3 with `not found` when the query matches no manifest path and no watch entry; 2 on a malformed ledger.

Implement the IMPT-05 adjacency edge with two real fixture cases in `tools/provenance/test/paths-resolve.test.ts`, both against the same synthetic `PATHS.json`, and assert the emitted `rule=` field so the deciding rule is visible, not inferred:

(a) **Exception beats prefix.** `docs/legacy/rpc.md` is covered by a `docs/` `prefix` rule and also named in `exceptions` with a different `to`; the exception decides, exactly one line is printed, and the line carries `rule=exception`. A second exception with `to: null` reports `absent` and prints no local path.

(b) **Prefix beats file rule.** `docs/rpc.md` is covered by the `docs/` `prefix` rule and also by an exact `kind: "file"` entry with a different `to`; the longer, more specific mapping is the prefix in this order, so the prefix decides and the line carries `rule=prefix`. This case exists because "the file rule wins" is *not* the contract — the contract is exceptions, then longest matching prefix, then exact file rule — and a test that asserted the file rule would encode the opposite order.

Add the empty edge: a path present in the manifest but with no watch and no rule resolves to identity with `watch=none` and exit 0; a path present nowhere exits 3.

Add the ordering edge as a unit case with three overlapping watch entries whose `upstream_paths` lengths differ (`a/b/c.ts` under `a/`, `a/b/`, `a/b/c.ts`) and whose ids differ (`WL-Z-…`, `WL-A-…`, `WL-M-…`): assert the emitted order is longest-path-first and, for equal lengths, byte-ascending id. Assert on the ordered array of ids, not on a substring of the whole output — a substring check cannot detect a wrong order.
