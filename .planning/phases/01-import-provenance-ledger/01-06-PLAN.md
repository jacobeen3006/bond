<objective>
**As a** maintainer, **I want to** prove that LFS-tracked binaries and lockfile bytes survived the import exactly as upstream committed them, **so that** a later build failure is a real defect rather than a corrupted import.

Purpose: these are the two fidelity surfaces that fail silently. An LFS pointer replaced by a payload bloat the repo and destroys blob identity; a lockfile regenerated by a tool changes dependency resolution while every source file still looks correct.

Output: a schema-valid LFS inventory for `oh-my-pi`, and a lockfile check that fails on byte drift and on an unlisted lockfile.

Reconciliation obligation (IMPT-06's unclassified edge, discharged at execution rather than assumed): the lockfile kinds observed at the four imported mains — `Cargo.lock`, `bun.lock`, `flake.lock`, and `MODULE.bazel.lock` in `oh-my-pi`; `flake.lock` and `uv.lock` in `hermes-agent`; `deno.lock` and `uv.lock` in `hindsight`; plus whatever `gsd-omp` ships — are the set the detector must recognise. Any further lockfile-shaped file is added to the ledger rather than ignored, and the detected set is printed on every run so a new kind is visible instead of silent. This is an obligation the executing agent discharges against the imported trees; it is not a fact this plan may assert.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LFS pointer → later build | A substituted payload is executable content in a later phase |
| lockfile → dependency resolution | Altered bytes change which packages a build installs |
| upstream `.gitattributes` → staging | An LFS declaration is the only signal that a blob is a pointer |
