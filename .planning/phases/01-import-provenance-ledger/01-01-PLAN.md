    - fetch: the only two selectors are `--tree &lt;name&gt;` and `--all`. `fetch --tree gsd-omp` (with or without the explicit `--resolve`) creates `upstream-cache/gsd-omp.git` (bare, `remote.origin.promisor=true`, `remote.origin.partialclonefilter=blob:none`) when absent, pins `refs/heads/main`, prints exactly one stdout line `resolved gsd-omp &lt;40-hex sha&gt;`, and writes that SHA as the single line of `upstream-cache/gsd-omp.resolved`. This is the form the `justfile` emits for a non-empty `tree`, so `--resolve` is accepted but never required.
    - fetch: `fetch --tree &lt;name&gt; --sha &lt;sha&gt;` skips resolution and asserts `cat-file -e &lt;sha&gt;^{commit}`, failing with exit 2 and `pinned commit missing` when absent. `import --tree &lt;name&gt;` without `--sha` reads `upstream-cache/&lt;tree&gt;.resolved` and fails with exit 2 and `no resolved sha` when the file is absent.
    - fetch: `fetch --all` (bare, and the explicit `--from-ledger` spelling is an accepted synonym for the same path) reads every `vendor/*/provenance/UPSTREAM.json.commit`, ensures each commit exists in its own cache (`cat-file -e`), fetching only that commit with `--filter=blob:none` when absent, and never re-resolves a branch. It is a no-op when every commit is present, which is what lets CI and `just verify` run it unconditionally after a cache restore or a fresh clone.
    - fetch: `fetch --tree <name>` takes its clone URL from the exported `TREE_REPOS` registry in `fetch.ts` — the single mapping from tree name to upstream remote — and never from a constructed string or an argv value. `TREE_REPOS` holds exactly four entries: `gsd-omp`, `hermes-agent`, `hindsight`, and `oh-my-pi`, each an HTTPS clone URL (the same four `repo` values the later imports record in `UPSTREAM.json`). A name absent from the registry exits 2 with `unknown tree: <name>` before any cache directory is created and before any network call. `TREE_REPOS` is a plain exported constant with no import-time side effects, so a test can read it without touching the network.
    - fetch: the resolved remote URL is validated against `^https://[^/]+/` before any network call on every path — for `--tree` from the `TREE_REPOS` entry and for `--all` from each ledger's `repo`. A non-conforming URL exits 2 with `insecure remote: &lt;url&gt;` and performs no network I/O; `git archive` is never given `--remote`, so archiving reads only the local cache.
    - stage: extraction runs three argv-array commands with no shell and no pipe — `git -C upstream-cache/gsd-omp.git archive --format=tar --output=&lt;tmpfile&gt; &lt;sha&gt;`, then `tar -tf &lt;tmpfile&gt;` to list entries, then `tar -xf &lt;tmpfile&gt; -C vendor/gsd-omp`. The `tar` on PATH is bsdtar 3.8.9 (`C:\Windows\System32\tar.exe`); the name `bsdtar` does not resolve on this machine and must not be used.
    - stage: every entry from `tar -tf` is passed to `paths.ts` before extraction; an absolute path, a `..` segment, a leading `//`, a `:` (ADS or drive), a `\`, or an empty segment aborts with exit 2 and `unsafe archive path: &lt;p&gt;`, leaving `vendor/gsd-omp/` untouched. A leading `./` is stripped before the check.
    - stage: `.git/info/attributes` is written with the single line `* -text -filter -ident -working-tree-encoding` before the first `git add`, and stage aborts (exit 2, `staging attributes missing`) if the file is absent at add time.
    - stage: modes are repaired after extraction — every upstream `100755` path gets `git update-index --chmod=+x`, every `120000` path is registered with `git update-index --add --cacheinfo 120000,<blob>,<path>` — because Windows cannot represent either.
    - import: after the archive-entry gate and before extraction, prints exactly one stdout line `SIZE <tree> files=<n> bytes=<n>` computed from `git ls-tree -r -l <sha>` (entry count and the summed blob sizes it reports), then `IMPORT OK <tree> files=<n>` on success. The size line is the only size signal in the phase: plans 01-03 and 01-04 read it rather than re-measuring, and every tree's import prints it.
    - manifest: output is `#halo-manifest v1` then `%06o<TAB><40-hex blob oid or -><TAB><64-hex sha256 of raw bytes><TAB><posix path>`, LF-joined with a final LF, no BOM, sorted with a byte comparator.
    - manifest: membership is fixed — `MANIFEST.upstream.tsv` covers every `git ls-tree -r` path, and `MANIFEST.vendored.tsv` covers every staged index path under the tree **except** those where `isLedgerPath()` is true (`provenance/` and anything below it). A `120000` row's `sha256` is the hash of the link text as stored in the blob (read with `git cat-file blob`), never of the materialized worktree file.
    - restage: `manifest --tree <name>` (the `restage` spelling is an accepted synonym) stages the existing worktree under `vendor/<name>/` with `git add -A` after asserting `.git/info/attributes` carries the exact staging line, recomputes `MANIFEST.vendored.tsv` through the same `stage.ts` + `manifest.ts` function the import uses — no archive, no extraction, no fetch, no cache access — and recomputes all four ledger digests over the files on disk. It prints `MANIFEST OK <tree> unchanged` when the recomputed manifest bytes equal the committed file, otherwise it rewrites `MANIFEST.vendored.tsv` and updates `UPSTREAM.json.manifests.vendored_sha256` in place, preserving the document's key order, indentation, and trailing newline so the diff is exactly that one value. A non-vendored digest (`manifests.upstream_sha256`, `excludes_sha256`, `renames_sha256`) that no longer matches the recorded value exits 2 with `ledger inconsistent: <ledger-path>` and writes nothing. `manifest --all` restages every tree carrying a `vendor/*/provenance/UPSTREAM.json`.
    - replay: accepts the same two selectors as fetch — `replay --tree <name>` for one tree and `replay --all` for every tree carrying a `vendor/*/provenance/UPSTREAM.json`. It first recomputes the SHA-256 of `MANIFEST.upstream.tsv`, `MANIFEST.vendored.tsv`, `EXCLUDES.json`, and `RENAMES.json` and compares them to `UPSTREAM.json.manifests.upstream_sha256`, `manifests.vendored_sha256`, `excludes_sha256`, and `renames_sha256`; any mismatch prints a `TAMPERED <ledger-path>` line for each mismatching file — `<ledger-path>` being the repository-relative path of the file whose digest failed, for example `vendor/gsd-omp/provenance/MANIFEST.vendored.tsv` — and exits 1 before a single file is compared, so a forged manifest cannot excuse drift.
    - replay: rebuilds into a fresh directory under the OS temp dir, applies `patches/series` in recorded order, then applies every `RENAMES.json` rule with `kind: "path"` in rule-id byte order (an empty map is the identity), and compares both manifests; prints one `path | expected | actual | kind` line per difference (capped at 200, then a count).
    - replay: a path-rename `from` or `to` that is absolute, contains `..`, or starts with `//` aborts with exit 2 and `unsafe rename: <id>` before any rule is applied; a rename whose `to` target does not exist in the reconstruction is exit 1 with `RENAME-TARGET <id>`.
    - replay: prints one `REPLAY OK <tree> files=<n>` line per replayed tree on success and exits 0; exits 1 on any drift or `TAMPERED` in any tree; exits 2 on a missing cache, SHA, or ledger file (`--all` reports every tree it replayed before returning, but its exit code is 1 as soon as one drifted).
    - replay: asserts every ledger file under `vendor/gsd-omp/provenance/` exists and parses, and asserts no `vendor/gsd-omp/**/.git` directory, no `.gitmodules`, and no index entry with mode `160000`.

`tools/provenance/manifest.ts` owns exactly one hashing/formatting implementation, used by both stage and replay: `hashFile(path)` returns the SHA-256 of raw bytes read with `node:crypto` (never through git filters), `hashBlob(oid)` returns the SHA-256 of the bytes `git cat-file blob <oid>` emits (required for mode `120000`, where the worktree may hold a materialized file rather than the stored link text), `formatLine(mode, oid, sha256, path)` renders one TSV line, `writeManifest(rows)` sorts with a `Buffer.compare` on the UTF-8 path bytes and writes LF-only, `readManifest(text)` parses back with a schema check that rejects a missing `#halo-manifest v1` header, CRLF, a BOM, or a duplicate path, and `isLedgerPath(relPath)` returns true for `provenance` and everything under `provenance/` — the single membership predicate every manifest writer and reader shares.

`tools/provenance/paths.ts` owns `assertSafeArchiveEntries(entries)` — the pre-extraction gate described above, throwing a typed error carrying `{ kind, path }` for `absolute`, `traversal`, `unc`, `ads`, `backslash`, and `empty-segment`. Plan 01-02 extends this same module with the Windows-representability findings (reserved names, case collisions, trailing dot/space, length); it does not create a second path checker.
