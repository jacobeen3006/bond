<objective>
**As a** maintainer shipping four MIT works in one product, **I want to** prove each licence and notice is byte-identical to upstream and make the future rebrand tooling structurally unable to touch it, **so that** redistribution stays compliant without relying on anyone remembering the rule.

Purpose: MIT's obligation is that the copyright notice and permission text travel with the work. The risk is not deletion — bulk `s/hermes/halo/gi` replacement leaves a notice that still says MIT but no longer identifies the work (PITFALLS P-02). Phase 1 cannot run the rebrand; it can pin the bytes and define the deny-list the rebrand must obey.

Output: a licence ledger per subtree, a machine-readable deny-list contract, and two tests that fail if either is violated.

Delivery boundary, stated rather than implied: Phase 1 delivers the pinned bytes, the deny-list contract, and the sensitivity test proving the contract would catch a violation. No rebrand rewriter executes in Phase 1 — the tooling that must consume this contract is Phase 2 (DEC-05), so ROADMAP SC#3's "cannot be modified by the rebrand tooling" is discharged here as an enforced contract plus a failing-if-violated test, not as an executed rewrite. Likewise the CI job that would run it needs a configured remote (DEC-09). Record both limits in the plan SUMMARY instead of claiming enforcement has run.

Scope note (estimate 100k at the 100k advisory budget, confidence low; ten files is exactly the ten-file line): no split is taken. Licence pinning and the deny-list are one predicate with two callers — the same matcher decides what `license.ts` pins and what the rebrand must skip, so splitting them would produce two matchers that can disagree.
</objective>
