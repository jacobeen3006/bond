<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> main IPC | Untrusted renderer frame; sender identity is untrusted input. |
| renderer -> daemon | The renderer must not reach the daemon transport directly (token isolation). |
| main -> daemon WS | The main process holds the token; the daemon trusts only the loopback main connection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-07 | Elevation of Privilege | renderer token access | critical | mitigate | Token lives only in the main process; negative test asserts the token is absent from renderer scope and a renderer fetch to the daemon port fails. |
| T-10-08 | Spoofing | ipc.ts sender validation | high | mitigate | Validate the IPC sender (senderFrame/frame identity) before handling; reject foreign/spoofed senders (test: spoofed sender rejected, legitimate accepted). |
| T-10-09 | Information Disclosure | renderer->daemon direct path | high | mitigate | No renderer network route to the daemon: loopback WS + sender validation; renderer fetch to the daemon port must fail (negative test). |
| T-10-10 | Tampering | single-instance / data dir | medium | mitigate | Single-instance lock (second launch focuses existing window); app data under %LOCALAPPDATA%; no multi-writer on app state. |
