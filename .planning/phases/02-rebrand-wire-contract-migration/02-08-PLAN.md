## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo content → gate output | The gate is the audit instrument; a soft-fail path or self-derived allow-list makes it decorative |
| CI workflow → build verdict | `continue-on-error`-style softening silently neuters SC#1 |
| allow-list → future regressions | Over-broad or dead entries hide tomorrow's half-rename behind yesterday's review |
| fixture tokens → gate trust | Fixtures are in-repo; a test that scans only fixtures proves scanning works, not that the repo is clean — both are asserted separately |
