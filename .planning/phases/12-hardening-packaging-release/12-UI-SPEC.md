# Phase 12 — UI Design Contract

> Visual and interaction contract for the Hardening, Packaging & Release phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Phase 12's user-visible surface: (1) branded installer (NSIS wizard + first-run setup overlay), (2) on-demand model provisioning, (3) About + Third-Party Notices, (4) crash/diagnostic cards (sidecar crash-loop, single-instance, orphan-reaper), (5) robustness error copy (>260-char paths, non-UTF8 child output), (6) credential redaction guarantee.
>
> **Inheritance rule (binding):** every surface reuses the vendored desktop design system (`vendor/hermes-agent/apps/desktop`). No new tokens, no raw hex, no one-off shadows or bespoke buttons (DESIGN.md: "tokens over literals, flat over boxed"). Locked user decisions: **model provisioning = on-demand download**; **NSIS installer = fully branded**.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Stage-row gaps, compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Screen padding (vendor progress header `px-6`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **44px minimum touch targets** when `hover: none` / `pointer: coarse` (inherited rule promotes composer controls to 2.75rem); **24px titlebar controls** (24×24 hit targets, 13.9px glyphs); corner radius is small by design — `--radius-scalar: 0.2` ⇒ md = 2px ("flat over boxed", DESIGN.md).

|------|-------|-------|
| Dominant (60%) | `#f8faff` light / `#0d0d0e` dark | Window chrome, installer screen backgrounds |

**Accent reserved for:** the primary CTA (Install HALO / Download models / Retry), the progress-bar fill, the active-stage marker, and focus/active strokes. Never for success states — stage-list completion uses a **muted check** (vendor rule: "no celebratory green"), never decorative fills.

Both light and dark palettes must render — installer overlay and diagnostics are read in both modes (OS-following, no switcher).

## Redaction & Robustness Guarantees (PLAT-05/06)

Binding UI-level rules for every Phase 12 surface:

1. **Credentials never render.** Model credentials live only in the secret store (AGENTS.md hard boundary). The log viewer, diagnostic card, installer live-log panel, and every error message render through the redaction pass: any credential-pattern match is replaced with `[REDACTED]` before paint. No "reveal" affordance exists in v1; settings show masked values (`••••••••`).
2. **Long paths degrade, not crash.** Any UI that displays a path longer than 260 chars truncates with an ellipsis, carries the full path in a tooltip, and links to the log. The documented error copy above is the only user-visible long-path state.
3. **Non-UTF8 never crashes a surface.** Child-process log lines pass through the `[NON-UTF8]` placeholder filter (RESEARCH.md §4); the LogView and diagnostic card must render the placeholder line verbatim without dropping the line or the session.
4. **Offline ≠ loading.** A failed/absent model download is a persistent degraded badge (orange `#db704b`), never a spinner; the UI must be fully usable in the degraded state (chat works, memory features show a "degraded" StatusPulse).
5. **Crash-loop is terminal until acted on.** After >5 crashes in 10 min the sidecar is `failed`: no silent auto-restart; the diagnostic card is the only UI state, and "Restart sidecar" is the only path back.

## Open Decisions

Genuinely open items where this contract made a sensible default (flagged for the planner, not blocking):

1. **Installer branding layering.** NSIS MUI cannot host a React webview, so "fully branded" is delivered in two layers: (a) the NSIS wizard itself is branded (HALO icon, accent `#0053fd` MUI theme, custom welcome/progress/completion copy from the Copywriting Contract); (b) the full 4-screen model (welcome → progress → success/failure, mirroring `bootstrap-installer/src/routes` 1:1) is the in-app first-run setup overlay at `--z-setup: 1400` — consistent with DESIGN.md, which already classifies "boot/install/update surfaces" as app overlays.
2. **Default model set.** Embed `BAAI/bge-small-en-v1.5` (33 M, 384-dim, ≈130 MB) + rerank `Xenova/ms-marco-MiniLM-L-6-v2` (22 M) — the AGENTS.md Standard-tier defaults. `bge-m3` (1024-dim) is an explicit opt-in quality tier with the latency warning; never the default.
3. **Installer overlay follows OS appearance** (vendor `theme.ts` model); no theme switcher in the installer or setup overlay.
4. **About omits update affordances** (PLAT-09 deferred to v2) — no "Check for updates", no update channel UI in Phase 12.
5. **Offline retry policy.** No automatic retry loop on failed downloads; exactly one user-initiated retry per failure; the degraded badge persists until a verified download completes.
