<objective>
**As a** HALO user on a Windows workstation, **I want to** launch the memory service once and have it bring up the bundled PostgreSQL+pgvector cluster, the embedder sidecar, and the embedded Hindsight API+worker, then land a retain as a vector row, **so that** memory works end-to-end with no Docker, no developer tools, and no manual setup.

Purpose: this is the phase tracer, split into a foundation slice (Task 1: supervisor scaffold → PG cluster boot → pgvector gate → health check, verified by `pg-boot.test.ts` before Task 2 runs) and an expansion slice (Task 2: embedder sidecar → embedded Hindsight → 2s-coalescing retain shim → one retain landing a vector row, verified by `memory-boot.test.ts`). It proves the whole architecture (the client-connection health check, the `asyncpg`/`postgresql://` wiring, the in-process worker, the `litellm` wire format, the `operation_id` idempotency) before any expansion layer is committed.

Output: the `packages/sidecars` workspace member (supervisor core + PG + pgvector gate + embedder + Hindsight + retain shim), the model manifest + schema, and the `pg-boot` (MEM-01) and `memory-boot` (end-to-end) tests.

Assumptions surfaced (from 08-RESEARCH.md Open Questions; all non one-way, carried as recorded decisions — no `checkpoint:decision` needed):
- Q1: the 2s coalescing window is a HALO shim (not a Hindsight change); the `operation_id` is the idempotency key.
- Q2: the chat LLM defaults to `HINDSIGHT_API_LLM_PROVIDER=none` (degraded: chunk-store + rrf failover); a third `llama-server` chat sidecar is NOT added without a recorded decision.
- Q3: `--pooling mean` is explicit in the embedder argv (not a default).
- Hardware-profile flag values (not enumerated in AGENTS.md; recorded here as the decision): Low (≤4 vCPU/8GB) `-t 4 -tb 4 -c 4096 -b 512 -ub 256`; Standard (8 vCPU/16GB) `-t 8 -tb 8 -c 8192 -b 1024 -ub 512`; High (≥16 vCPU/32GB) `-t 16 -tb 16 -c 16384 -b 2048 -ub 1024`.
</objective>
